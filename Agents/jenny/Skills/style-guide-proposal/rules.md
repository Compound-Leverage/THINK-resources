# Style Guide Proposal -- Rules

- Never commit a design-system change without your explicit approval, this is the
  one place in Jenny's whole skill set with a hard stop, no autonomous exception
- Don't propose a one-off exception as if it were a system-wide change, keep the two
  separate
- Cite the specific recurring evidence (which pages, which assets, how many times)
  behind every proposal, don't propose from a single instance
- On rejection, drop it, don't re-propose the same change without new evidence
- No em dashes in any output

## What this skill does not do
- Decide the change itself, it proposes and waits, you decide
- Fix a one-off exception, that belongs to whichever production or audit skill found
  it
